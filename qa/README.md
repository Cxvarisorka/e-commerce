# QA Documentation — Lulshop E-commerce

Generated by the `qa-test-docs` skill. All test cases are grounded in the
actual backend code (routers, controllers, validations, models) as of
**2026-05-30**.

## Test environment

- **API base URL:** `http://localhost:<PORT>/api` (see `server/.env`, `PORT`)
- **Auth:** JWT in an **httpOnly cookie** named `jwt`. Send credentials with
  every protected request (browser cookie / `--cookie` / `withCredentials`).
- **Roles:** `user` (default), `seller`, `admin`.
- **Required test accounts:**
  - Verified `user`
  - Verified `seller` (with `stripeAccountId` set, for payments)
  - Verified `admin`
  - Unverified user (for email-verification gating)
- **Error shape:** errors flow through `AppError` → global handler. Assert on
  HTTP status code + `message`.
- **Success shape:** `{ status: "success", message, data }`.

## Conventions

- **Case IDs:** `TC-<AREA>-<NN>` (stable, do not renumber).
- **Status values:** `Not Run` · `Pass` · `Fail` · `Blocked`.
- **Priority:** Critical · High · Medium · Low.
- **Type:** Functional · Negative · Security · Boundary · Authorization · UI.

> ⚠️ Cases marked **[DEFECT-WATCH]** assert the *correct/standard* behaviour but
> are expected to fail against the current code — they document a likely bug
> found while writing the tests. See the note on each.

## Coverage standard

Every feature file covers, at minimum: happy path, required-field/negative
validation, authentication (no token), authorization (wrong role / wrong
owner), not-found, and relevant boundary values. See
[../.claude/skills/qa-test-docs/references/ecommerce-standards.md](../.claude/skills/qa-test-docs/references/ecommerce-standards.md).
